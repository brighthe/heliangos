# 微信沟通模块（wechat）

存储我与工作对象的微信聊天记录、每位对象的沟通口径，并在此基础上协助我起草回复。聊天记录按**阶段/场景**分子模块归档。

## 目录结构

```
wechat/
├── README.md                       # 本说明
├── 大连理工大学博士后/              # 子模块：我在大工做博士后期间与相关老师的沟通
│   ├── README.md
│   ├── _TEMPLATE.md                # 新建老师档案的模板（复制它）
│   └── teachers/
│       └── <姓名>.md               # 每位老师一个文件：档案 + 关键信息 + 未决 + 聊天记录
└── 高校求职/                       # 子模块：我求职高校教职期间与各校的沟通（按学校再分一层）
    ├── README.md
    ├── _TEMPLATE.md                # 新建联系人档案的模板（全校共用）
    └── <校名>/                     # 每所学校一个文件夹
        ├── README.md              # 本校概况 + 联系人索引
        └── contacts/<姓名>.md     # 每位联系人一个文件
```

将来若有别的阶段或单位的沟通，在 `wechat/` 下再开一个同构的子模块即可。

## 两类工作

### 1. 记录聊天（我发截图，Claude 只存文字）

我把与老师的微信**聊天截图**（或直接粘贴文字）发给 Claude，用 `/log-chat <老师>`：Claude 读截图 → 按时间顺序转写成文字 → 去重后追加到对应老师 `.md` 的「聊天记录」段 → 并据此更新其档案与待办。

> **不保存截图**，只保留可搜索的文字记录。Claude **不**用 computer-use 去驱动微信（实测又慢又容易被其他窗口抢焦点）。

### 2. 起草回复（只起草，你自己发）

用 `/draft-reply`。Claude 读这位老师的档案与历史聊天 → 必要时用 `intent-analyst` 拆来意 → 按 `wechat-work-style` 起草草稿 → **你自己复制发送**。重要回复发出前可用 `reply-reviewer` 审一遍。

## 隐私

本模块内容高度敏感（真实人名 + 私聊），且仓库为 Public、公开可见；写入前对敏感内容从严把关、必要时脱敏，聊天原文不主动外发到其他服务、不联网检索。
